# Ubiqx AI Studio Technical Constraints

Status: Baseline for v1
Last updated: 2026-08-13

## Purpose

This file records the technical choices and limits that the v1 implementation must respect. Product decisions are in `PRD.md`; architectural decomposition is in `ARCHITECTURE.md`.

## Stack

### Front End

- Vue 3 with TypeScript.
- Vite for development and build.
- CanvasKit for canvas rendering.
- Pinia for client-side project and scene state.
- A generated OpenAPI client for REST calls.

### Back End

- FastAPI on Python 3.12.
- Pydantic for request, response, and scene model validation.
- SQLAlchemy for local metadata persistence.
- SQLite for v1 metadata.
- A local filesystem-backed asset store.
- OpenAPI generated from FastAPI route and schema definitions.

These backend choices are provisional v1 defaults. The contract boundaries in `ARCHITECTURE.md` and `API-CONTRACT.md` should remain portable if the backend runtime changes.

## Runtime and Storage

- The v1 product is local-first.
- Metadata lives in a SQLite database in the user's project data directory.
- Binary assets are content-addressed by SHA-256 and stored in a separate asset directory.
- Project autosave writes are debounced and must be idempotent.
- File operations must not overwrite an existing asset with a different content hash.

## Image and Design Format Limits

- Working color space: sRGB.
- Bit depth: 8 bits per channel.
- Pixel format: RGBA.
- Alpha mode: straight alpha.
- Maximum processed or exported dimension: 4096 pixels on any side.
- Inputs larger than the maximum are downsampled with an explicit warning.
- Import formats: PSD, PSB, PNG, JPEG, WebP, and SVG.
- Asset export formats: PNG, JPEG, WebP, and SVG.
- V1 project export: self-contained HTML5 package.

## PSD/PSB Preservation

- Preserve document bounds, layer hierarchy, groups, names, visibility, opacity, transforms, text layers, and image assets where practical.
- Preserve unsupported layer effects as metadata instead of silently dropping them.
- Text layers must retain text content, font name, size, color, and alignment when available.
- Import must produce a stable scene graph even when some properties cannot be represented.

## Scene Graph Constraints

- The scene graph is the source of truth.
- The canvas is a view over the scene graph and never the canonical data store.
- Every canvas operation must translate into a scene-graph mutation that can be undone and replayed.
- Node IDs are stable UUIDs generated by the backend.
- Parent-child relationships must remain acyclic.
- Transforms use a common numeric representation with no implicit unit assumptions.

## Canvas Constraints

- CanvasKit is loaded asynchronously.
- The canvas must remain usable for typical imported UI documents.
- Large assets must be downsampled for preview when necessary without changing source assets.
- Selection, move, resize, zoom, and pan must not require a page reload.

## AI Constraints

- Text and image providers are behind a common provider interface.
- AI work is asynchronous.
- Every AI task has a status, timeout, retry budget, cancellation path, and cost/usage record.
- Default retry budget: at most three attempts per task.
- Retries use exponential backoff and must not run indefinitely.
- Provider credentials are never sent to the browser.
- Provider-specific responses are normalized into internal result types.

## API Constraints

- REST API is versioned under `/api/v1`.
- OpenAPI is generated from the implementation and committed as a contract artifact.
- Responses use JSON.
- Errors use one stable error envelope.
- Mutating operations use idempotency keys where retry safety matters.
- Long-running operations return a task resource and support polling.

## Security Constraints

- Uploads are validated by declared type, detected type, extension, and size.
- File paths are derived from content hashes, never from user-provided names.
- Imported files are treated as untrusted input.
- API keys are stored hashed, not in plaintext.
- Secrets are supplied through environment variables or a local secret file.
- The browser never receives provider credentials.

## Browser Support

- Primary support: current Chrome, Edge, Firefox, and Safari.
- CanvasKit must degrade gracefully when WASM initialization fails.

## Performance Targets

- Project list loads within 2 seconds on a normal local machine.
- Opening a typical imported UI project reaches an interactive canvas within 5 seconds.
- Autosave does not block pointer interactions on the canvas.
- AI task polling remains responsive with the v1 local task runner.

## Network Constraint

- The local development and production environment may have restricted network access.
- Core import, canvas, autosave, and HTML5 export must work without external network access.
- AI features and Figma import are explicitly network-dependent and must fail cleanly when unavailable.
